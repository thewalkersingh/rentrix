Git Publish
0.x.y → pre-1.0, actively developing
x.1.y → feature milestone
x.y.1 → patch


After publishing
- GitHub creates a tag v0.1.0 on the current master commit
- A "Release" appears on your repo's /releases page
- If you later set up CI/CD, you can trigger deploys on tag push:

on:
  push:
    tags: ['v*']
- Render + Vercel will still deploy from master pushes — releases are just a documentation/versioning layer on top
